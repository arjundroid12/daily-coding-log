## 🧠 Challenge of the Day

### Fibonacci (Efficient)

**Difficulty:** Medium
**Topic:** Dynamic Programming

**Problem:**

Return the nth Fibonacci number. F(0) = 0, F(1) = 1, F(n) = F(n-1) + F(n-2). Handle n up to 50 efficiently.

**Example:**

```
Input: 10
Output: 55
```

**Hint:**

Naive recursion is O(2^n) — way too slow. Memoize, or iterate bottom-up keeping only the last two values.

<details>
<summary>🔍 Reveal solution</summary>

```javascript
// Bottom-up, O(n) time, O(1) space
function fib(n) {
  if (n <= 1) return n;
  let prev = 0, curr = 1;
  for (let i = 2; i <= n; i++) {
    [prev, curr] = [curr, prev + curr];
  }
  return curr;
}

// With memoization (top-down)
const memo = new Map([[0, 0], [1, 1]]);
function fibMemo(n) {
  if (memo.has(n)) return memo.get(n);
  const result = fibMemo(n - 1) + fibMemo(n - 2);
  memo.set(n, result);
  return result;
}
```

**Explanation:** Bottom-up with two variables is optimal — O(n) time, O(1) space. Memoization is O(n) time but O(n) space.

## 💡 Tip of the Day

**Use `Object.hasOwn(obj, key)` instead of `obj.hasOwnProperty(key)`**

Modern JS (ES2022) provides `Object.hasOwn(obj, key)` as a safer alternative to `obj.hasOwnProperty(key)`.

Why safer? If someone creates an object with `{ hasOwnProperty: 'lol' }`, calling `.hasOwnProperty()` on it will fail. `Object.hasOwn()` is a static method — immune to prototype pollution.

```js
// ❌ Risky
obj.hasOwnProperty('key')

// ✅ Safer
Object.hasOwn(obj, 'key')
```
